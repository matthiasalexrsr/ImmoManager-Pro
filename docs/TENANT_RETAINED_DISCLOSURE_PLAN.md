   workflow subject identities from the stored previous/next contract snapshots,
   not current contract party names or inferred text. SQL must restrict candidates
   before materialization and preserve scope/parent checks; Memory uses the same
   explicit identity proof.
2. Validate available immutable hashes, source/start/publication/response bindings,
   exact membership and parent chains. Reject corrupt or incompletely read facts

   partial or damaged families fail without automatic schema repair.

   counterpart's contract/snapshot/steps and command-response parts explicitly.

   cursors, leases, tokens or other tenants' receipt responses. Current-only source
   references cannot prove an unrecorded earlier tenant identity. Unbound/tombstone
   records are not inferred from free text and this boundary is explicit.

   plan hashes. Add the focused retained-personal-evidence notice to the directly
   related preview projection; retain the existing profile-only mutation policy.
6. Test real Memory, SQLite and isolated PostgreSQL images where applicable:
   historical party correction, turnover redaction, shared-job isolation, complete
   uncapped iteration, source/projection hash changes, corrupt links/receipts,
   reader/scope revocation, stable snapshot despite concurrent writes, and stale
   reviewed hash refusal. No normal mutation/auth/schema/router/frontend edits.

The helper must state what actual data proves, including unavailable historical
job-party bindings and irreconstructible workflow original requests.
