Root composition after the pre-code `BILLING_DISPUTE_COMPOSITION_PLAN_20261003`.
The complete j2 Domain journal and k2 meter index are integrated. Early model

## Result

The new `billing_dispute_database` proof reads actual raw SQLite or SQLAlchemy
connections without auth, settings, application, Store or provider imports.
It validates native schema, immutable guards and every actual FK before paging
case identities. Each case's full commands, original events, correction lineage
and evidence receive the existing pure journal proof. The affected period hash
uses every statement, including other tenants' statements, streamed in exactly
the existing canonical settlement JSON. A small internal period-hash LRU is a
work cache, never an externally supplied proof or history cutoff.

Full-backup image approval and staged file validation call the proof. Restore
security/worker normalization calls it before its first update. Broken original
reason, receipt, chain, evidence binding or sibling statement blocks approval;
ordinary key rotation and session invalidation cannot hide the defect.
An entirely absent old journal remains supported; a partial or weakened family
fails. Business subset export/import/reset refuses retained originals behind
the existing writer barriers and cannot silently discard the journal.
