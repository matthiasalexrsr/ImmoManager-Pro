## Actual present paths and evidence gaps

`billing.download_utility_statement_pdf` (current basis around line 1038) loads
UtilityStatement and creates reportlab bytes on every call. It renders today's
Unit.label (catch-all fallback to unit ID), contract ID, revision, financial
line_items/totals. It does not verify snapshot_hash, period status, frozen party,
source original JSON, period dates or archived bytes. It prints no tenant name;
there is currently no wrong current-tenant-name fallback to remove. The fallback
without reportlab is plain text. Explicit statement GET remains typed DTO only.
Bulk period ZIP calls this same renderer, so source hardening must cover that
call path too. These generated bytes are not an archived immutable PDF original.

New finalizations already prove actual original party in the existing hashed
owner JSON. The original contract freezes tenant ID/name/postal identity and
concrete parent/source references; it does not freeze Unit.label/Property.name.
Statement canonical hash includes financial rows/calculation_hash and excludes
mutable status/delivery fields. Period label itself is not in that hash. Do not
claim today's editable labels as finalization-era original labels or silently
invent missing historical names. Retained historical measurement sources prove
only their explicitly captured fields, not arbitrary later display metadata.

## First bounded product: true source/render validation

New own source service reuses billing_disputes.work read authority/snapshot,
existing streamed statement_snapshot_hash, pure party model and canonical
UtilityStatement JSON. Validate actual immutable statement + period, real stored
hash against complete actual period bytes, complete exact statement binding,
actual source chain and frozen party before rendering. Copy only the selected
statement's source JSON and selected party; never include every tenant family
from the period. Exact source JSON digest is recorded separately from existing
whole-period original SHA so both meanings are explicit.

Use only proved frozen name/postal identity. Legacy absence remains explicitly
historical-party-unproven: no current Tenant.full_name/Contract.tenant_id becomes
historical identity. Prefer true retained historical labels only if their
actual original proof is found; otherwise stable source references and clearly
captured display-at-publication context. After finalization profile/unit-label
change must not silently rename the original identity. Reject malformed present
party blocks rather than treat them as legacy.

Use existing bundled NotoSans fonts and reviewed PDF patterns (housing
confirmation/contract PDF), escaped text, line wrapping and repeated multipage
table headings. No successful text fallback for an explicitly requested PDF
original; report missing renderer/runtime concretely. Test exact financial
positions and Unicode/long-name/multipage layout with rendered PDF inspection.
A displayed re-render remains a validated derived preview until explicitly
published; reading must not create a document or claim delivery.

## Explicit original publication reuses real document archive

`document_versions.publish_generated_original` already publishes exactly one
first PDF original with metadata_extra, immutable DocumentVersion row/chunks,
content SHA/size, actor/request digest and existing `persist_version_bytes`
inside the caller's transaction. Existing read/download prepares and verifies
stored chunks. Use this archive and normal receipt/read URLs. No second archive,
DDL, arbitrary file URL rewrite or private alternative chunk store.

A review/confirmed publication binds statement ID/revision/original SHA, exact
source JSON digest, renderer profile version and prepared PDF content digest.
The actor reviews meaningful original details, then the publisher rechecks
fresh billing/document authority, original scope/source, tenant/property/root
period locks and prepared bytes through actual commit. Source changes reject
rather than rebase the reviewed command. Generated document creation, manifest,
chunks and receipt are one transaction with Memory undo. A repeated exact
command returns the original receipt/bytes; changed content under that key is
rejected. Existing immutable command/manifest keys must be reused for that
receipt, with deterministic document identity/source binding or a clearly
bounded existing receipt, before considering any migration. Duplicate users
and independent SQL connections need native uniqueness/race proof.

Minimal typed `utility_statement_original` metadata_extra records a versioned
source proof, selected statement/party original JSON, canonical source digest,
actual statement/period/revision/snapshot SHA and renderer profile. General
Document metadata and original URL stay their established contract. New pure
subtype validation must prove the actual retained source and manifest subject;
merely recomputing a metadata hash cannot legalise another source or party.

## Shared subject invariant that must be coordinated

The current generated publisher compares caller binding with `_document`, which
projects the *current* contract tenant. `_authorized_version` also requires
current contract tenant == archived tenant. Pure/native document recovery
currently asserts that equality for every contract-linked archive and forbids
a tenant without contract. Therefore blindly copying frozen tenant into a new
DocumentVersion is insufficient when independent native state has changed the
current contract party. No general relaxation is acceptable.

For the new typed utility-original subtype only, an independently verified
actual statement/period hash and pure frozen original party must authorise the
retained tenant subject at generation/read/privacy/offline validation. Generic
manual documents keep their existing current-binding invariant. Root owns the
central native/recovery/hooks; a precise pure subtype hook and actual source
references must be supplied. Shared Documentservice coordination is required
before any concurrent source edit. Ordinary parent guards continue preserving
all real source and document parents, with no source overwrite.

Legacy PDF has no proven historical tenant. A current contract-derived archive
subject must never be labelled as original identity. The conservative source
proposal is property/unit-only Document binding, contract/statement references
inside the actual financial-source proof and explicit historical-party-unproven
mode. This fits existing nullable archive parents without fictional tenant IDs;
Root must align its handling with exact privacy/evidence semantics before code.
Alternative present-time reviewed assignments must be explicitly labelled
publication-time evidence and cannot retroactively prove old original parties.
