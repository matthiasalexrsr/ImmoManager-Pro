# G06.2 local contract correspondence Core

Base: Root `2ed90ff`; separate prerequisite is the reviewed G06.1 Memory lock-order fix `587f3a4` (locally cherry-picked as `c577b98`). Pick the new correspondence commit only after Root has that prerequisite. No UI, Root startup, production data, preview or SMTP change belongs to this package.

## Delivered local workflow

1. An authorized contract manager records an explicit letter date, management deadline, deadline basis, recipient, subject and either plain text or an immutable existing G07 template version. `deadline_confirmed=true` is required. No notice-period or legal-date inference occurs.
2. Review captures the exact contract ETag and typed source snapshot, current parent/tenant ETags and display context, selected template version and optionally an accepted G06.1 confirm/finalize command. Only an allowlist of plain `{{name}}` variables is expanded. Nothing executes template code or emits active HTML.
3. Explicit approval checks draft revision, contract ETag, review hash, fresh actor/grants and all reviewed sources. It atomically publishes one Document, its first immutable DocumentVersion with PDF original chunks, the frozen approved letter and one command receipt. A failure at chunks, journal or final role check rolls back everything. Same command/key/input replays the stored response; differing input conflicts. No contract, obligation, payment or cash movement is created.
4. Separate immutable manual observations record dispatch or receipt. These are **human observations**, not an SMTP delivery guarantee, proof of legal service or electronic signature. Each event uses draft revision plus independent per-letter event revision/CAS. A receipt references an earlier dispatch on exactly the same letter and cannot predate it. A new dispatch requires current reviewed sources. A later actual receipt may still be recorded after those sources change. Approved letters never reopen; create a new letter when review is needed.

Private drafts belong only to their actor. Approved history is visible to users who can currently read the exact contract/tenant/parent portfolio path, including readonly users. Subject reparenting or a corrupt hidden journal/original is fail-closed; checks expose only a Boolean for an already authorized exact subject.

Writes require the existing contracts/rental capability; approval additionally requires the existing documents capability because it publishes a real Document original. This does not extend any role. Both currently supported rental-writing roles (owner and manager) already have documents capability; a future narrower role must receive an explicit policy decision. A server 403 remains authoritative.

## HTTP contract

Mount `backend.routers.contract_correspondence.router` before generic contract-ID handlers. Prefix `/api/v1/contracts/{contract_id}/correspondence`.

| Path | Input / output |
|---|---|
| POST `/drafts` | `CreateLetter`: key, expected_contract_etag, data; private draft result |
| GET `/drafts` | own drafts; `before`, positive `limit`; items/next_before/has_more/persistent |
| GET `/history` | immutable approved letters, same paging |
| GET `/deadlines` | approved user-confirmed date+basis, source_review_status and review_hash |
| GET `/drafts/{id}` | fresh authorized private/approved read |
| POST `/drafts/{id}/edit` | `EditLetter`: key, expected_revision UUID, expected_contract_etag, data; clears old review |
| POST `/drafts/{id}/review` | `RevisionCommand`: key, expected_revision, expected_contract_etag |
| GET `/drafts/{id}/review-pdf` | private reviewed PDF, no-store, SHA header, exact bytes or recoverable review conflict |
| POST `/drafts/{id}/approve` | RevisionCommand + reviewed_hash + confirmed:true |
| POST `/drafts/{id}/events` | `ManualEvent`: key, expected_revision, expected_event_revision, kind dispatched/received, event_date, channel post/handover/other, reference, note, confirmed:true; dispatch_event_id required only for received |
| GET `/drafts/{id}/events` | bounded before event revision; items/event_revision/next_before/policy |
| GET `/drafts/{id}/download` | complete approved original through existing PrivateDownloadResponse cleanup/role refresh, SHA/size/no-store |

Types are exact extra-forbid Pydantic models. Booleans are strict and must be true. Keys are stable per-actor command identities. 412 means stale contract ETag; 409 means revision/review/source/event/key conflict requiring review; 404 never exposes another private/foreign record. On uncertain network/write response retain the exact input and idempotency key. Do not automatically generate a new key or repeat a stale write.

Public letter fields: id, contract/portfolio/property/unit/tenant/actor IDs, UUID revision, state draft/reviewed/approved, data, source_contract_etag, review, review_hash, document_id/version_id, UTC created_at/approved_at, persistent, delivery_policy=manual_observation_only, download_url. Fresh GET/List add current_contract_etag and source_review_status=not_reviewed/current/requires_review. Immutable command replies intentionally remain the exact historical response, without pretending it is a fresh source-state read.

Review contains data, source_contract and ETag, source_context (portfolio and property/unit/tenant ETags plus allowed display names), selected template identity/version/body hash or null, accepted lifecycle command/draft/review/result hash/current_state or null, rendered_body and pdf_sha256. Lifecycle supersession or current source metadata changes require a new review before a new dispatch. Existing historical reviews/results are never edited to match newer sources.

Available placeholders: contract_number, tenant_name, property_name, unit_label, start_date, end_date, deadline_date, deadline_basis, recipient_name, recipient_address. Unknown/malformed placeholders fail visibly. Template selection uses the existing `/contract-wizard/templates` API and exact immutable template ID; newer template versions do not silently replace the selected version.

## Transaction and persistence

Migration `a2a2b3c4d5e6` follows `z1a2b3c4d5e6`. Three tables are an atomic compatibility set: contract_correspondence_drafts/commands/events. None present is a valid pre-a2 archive; partial presence is invalid. Frozen migration DDL and repeatable `ensure_contract_correspondence_schema` install guards. Commands/events prohibit UPDATE/DELETE; approved drafts prohibit UPDATE and all drafts prohibit DELETE. No schema table replacement is performed.

Approval reuses Lifecycle.Work's single independent transaction, Property→Unit→Contract locks and touched-row Memory undo. Memory account→domain order is held with existing `_memory_privacy_lock`, including actual auth refresh. SQL-auth writers take the existing auth_setup management marker before domain locks and refresh grants after waiting. Tenant SHARE then location/contract locks keep the letter source coherent with privacy and version writes. Neither facade create_document nor DocumentVersion public work is called, so no hidden early commit or second publication transaction exists.

Shared DocumentVersion extraction is narrow: `persist_version_bytes` writes a manifest plus bounded 64KiB chunks within its caller's transaction. Existing publish delegates its old chunk loop to it. `publish_generated_original` authorizes document capability and validates an exact freshly created Document binding/first-original PDF before calling the primitive. Memory uses caller-supplied per-row undo callbacks, including tuple chunk keys; no installation-wide deepcopy.

PDF review rendering is deterministic only within the installed renderer. Approval/review-pdf verifies its SHA; a renderer update before approval causes renewed review. **Approved historical originals are never regenerated for download or recovery.** Their stored chunks/size/SHA are authoritative, preserving readability across future renderer versions.

## Verification and limits

Native focused suite covers real Memory and SQLite, strict confirmations, private/foreign scopes, full build_api_v1 JWT+Portfolio+DB middleware, late chunk/journal/auth rollback, same-key replay, competing event CAS, immutable native triggers, fresh full Alembic chain, SQL schema parity, bounded tied paging, immutable templates, accepted lifecycle supersession, source-gone SQLite and actual encrypted FullRecovery→source removal→restore/download/manual history. A recovery test injects the proposed pre-security validator at the real existing transaction boundary; Root hook registration itself remains separate.

Independently reproduced event-response corruption is rejected before exact retry and by offline validation: the entire event response must equal the actual immutable event, including its note, actor, revision, creation time and manual-observation policy. Own actual Memory/SQLite red failures became three passes (one SQL-only skip) with unchanged event rows. Another own three red failures prove that an approval response may not point at a different Document/URL; the complete approved snapshot is now compared with the immutable approved row. Historical private draft responses remain their captured state.

The current reviewed state or approval's expected private revision must be backed by exactly one matching review command and its review hash. Deleting this exact review is rejected even when the approved original remains healthy. Checks follow causal revision identity, not wall-clock ordering. `validate_review_binding(draft,expected_revision=...,review_revision=...,review_hash=...)` exposes the same metadata-only binding for G43; callers must select exactly one authorized review command for this actor/draft/subject. `validate_command(command,draft)` verifies typed request/result evidence, `validate_event_response(command,event)` checks the exact immutable response. These helpers never export an unrelated actor's private text.

PostgreSQL file `backend/tests/test_contract_correspondence_postgres.py` owns a disposable UUID schema, real a2 Alembic upgrade, separate pg_backend_pid transactions, approval replay, late rollback, role revocation and event CAS. Register it in the actual PostgreSQL CI step. Local PG is skipped without TEST_SERVER_DATABASE_URL; no local PostgreSQL pass is claimed.
