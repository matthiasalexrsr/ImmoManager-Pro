# Changelog

All notable changes to ImmoManager Pro will be documented in this file.

## 2.0.0-beta.1 — first beta (2026-10-24)

The version is now `2.0.0-beta.1`: the scope of 2.0.0 is complete and tried by users before the release. It contains everything below (the 2.0.0 release candidate and rounds 1–18 since), and round 19:

- **Lists on a monitor (1280–1920 px, every page, tab and form measured):** from 1366 px no list scrolls sideways. Secondary columns are hidden by default and can be shown under "Spalten anpassen"; context stands beneath the main value (contract under tenant in bookings, unit under property in insurances and calendar, invoice number under supplier, origin under the description of a receivable). Names and addresses are no longer squeezed to their longest word, e-mail addresses break only after the "@", sort arrows stay beside their heading, "Summe (n)" no longer widens the first column, percent and area values carry a no-break space ("98 %", "68,50 m²"). Row actions that showed text got icons; the receivable residual is compact. Below 1440 px the sidebar, margins and cell padding are a little narrower; file tabs fit at 1280 px. Dashboard tiles of a row are equally high with aligned figures; one chevron per collapsible area; the current menu entry is scrolled into view; the assistant no longer cuts its empty chat in a short window; viewings show German dates.
- **Saved column settings and updates:** saved views and list settings record the columns hidden by default when they were saved (`hidden_defaults`, accepted by the server). A saved value that differs from that default is the person's choice and stays; every other column takes today's default, so a column an update hides reaches lists saved before it. Columns stand in the program's order (no list lets a person move one).
- **Release workflow:** it first waits for the CI run of the same commit and stops unless it passed. Besides a tag `v*`, a push that changes the packaging (`release.yml`, `immomanager.spec`, `packaging/`, `requirements-build.txt`) builds and tries the package as an artifact, publishing nothing (a manual start needs the workflow on the repository's default branch).
- **Dependencies:** pypdf 6.21.2 (crafted PDFs could cause long runtimes), undici 7.30.1 and zod 4.6.7 (test and lint tools).

## 2.0.0 — release candidate (2026-10-14)

The version is now 2.0.0 (`pyproject.toml`; it was still 1.0.0 although 1.2.0 had been released). Everything under "Unreleased" below is part of it; the German release notes for users are in [docs/RELEASE_NOTES.md](docs/RELEASE_NOTES.md).

- **Release workflow** "Release (Windows)": a tag `v<version>` matching `pyproject.toml` builds the Windows package with a German "LIES MICH.txt" (install, data folder, backup, update, restoring the pre-upgrade backup). It tries a first start, the upgrade check, a full backup, a restore probe and the update from the previous release's package on the same data. Then it publishes the GitHub release; a version with a suffix becomes a pre-release.
- **Update check for every installation:** it reads this repository's releases by default (`UPDATE_REPO_URL`), and only when "Jetzt prüfen" is clicked. The Windows package was refused the check altogether; it now learns about a newer version, gets the download link and is told what happens to its data. Only git checkouts install updates themselves (`can_apply`).
- **Second backup target in the app:** the owner sets the folder every full backup is copied to (USB drive, NAS) under Einstellungen → System → Betrieb. Before it is kept, the folder is created and a test file written; a relative path, the data folder itself or a file is refused with a sentence. `BACKUP_SECOND_TARGET` still wins and is shown as fixed. The overview now tells a target that is waiting for its first copy from a failed copy, and warns when the target is on the same drive as the data. The passphrase notice names the file to put `BACKUP_PASSPHRASE` in.
- The Aktenwerk manifest preview no longer carries a fresh timestamp, so the same data gives the same answer (it made the portfolio-scope comparison of all read endpoints fail at random).

## Unreleased — 2026-10-22 Round 16: owners and their shares

Properties and units can belong to different owners, several of them by shares, and the owners can change over time: [docs/OWNERSHIP_20261022.md](docs/OWNERSHIP_20261022.md). Two migrations add two tables and a column (`c9a1b3d5e7f9`, `d0b2c4e6f8a1`); without recorded shares no figure changes.

- **Shares:** an owner (a contact of type "owner") holds a percentage of a property or one of its units, from and until a day. On any day the shares add up to at most 100 %; the rest belongs to nobody recorded ("Ohne Eigentümer"). A unit's own shares come before its property's. Money of the whole property follows the property's shares, without them the units' owners by living area. A booking can name the owner it belongs to alone (a withdrawal, a cost one owner bears).
- **Changes of owners:** sale, gift, inheritance, division, sale to an outsider, in one step (`POST /ownership-shares/transfers`). The giver's share ends the day before, a rest continues, the receivers' parts start on the day and merge with a share they already hold. With scope "all", everything the giver holds in a property changes hands. A change before a later one, a share with a fixed end and receivers not adding up to 100 % are refused. A journal keeps every change; the property's "Eigentümer" tab shows the owners on any day, the periods between changes and the journal.
- **To the day and to the cent:** money of a day follows that day's owners; money of a period (a month's rent, a statement's months, an invoice's service period, a budget year) is split by the owners' days in it. Every amount is split among all owners at once by the largest remainder, so the reports per owner add up to the whole.
- **Owner filter** (also "none" for the unowned part) in the summary, finance, occupancy, aging, cash flow, period result, maintenance costs, liquidity forecast and PDF reports, in the finance reports v2 and saved definitions (their hash is unchanged without an owner), the budget analysis and the dashboard's money tiles. New report "Ergebnis je Eigentümer" (`/reports/owner-results`, also CSV): rent due, other income, costs, result, withdrawals and contributions per owner.
- **Tax:** the annual projection has the owners' parts per property and form line (`owner_split`); it enters the preview hash only when shares exist.
- **Review list:** "Eigentumsanteile unvollständig" names units and properties with a part no owner is recorded for, once a property has shares.
- Deleting a property, unit or contact with shares, changes or owned bookings is refused with the reason; data export format 15.

A test names a new head missing from `ORM_ADOPTION_TARGETS`.
- **The same IBAN cannot be entered for two accounts** in any store (compared without spaces; the existing account is named). Before, only a new SQL installation refused the exact spelling with a generic error. One IBAN check (`sepa_rules.iban_problem`) for accounts and direct debits.

- **Utility statements:** the advance sections round half up like the advances (525.105 € showed as 525.10 €, the sections did not add up).
- Only the owner changes where updates come from (`/updates/configure`), as only the owner installs them.
- The backend suite was also run with the clock moved to 2027-04-01 and 2028-01-03. Two tests would have failed by themselves: the test version test asked the review list for the real date instead of its data set's day, and a retention test expected a 2017 invoice to stay locked (ten years end on 31.12.2027); it now uses an invoice nine years old. The other differences came from the time-shifted test setup.

## Unreleased — 2026-10-20 Round 10: retention periods, index rent, lists

- **Retention periods with a deletion lock:** every document has a retention class, chosen on the document or implied by its type: booking records 8 years (§ 147 Abs. 3 AO and § 14b UStG as amended from 2025), books and tax papers 10, business letters and other papers 6, contract papers 3 years after the contract ends (limitation; a recommendation), permanent, none.
