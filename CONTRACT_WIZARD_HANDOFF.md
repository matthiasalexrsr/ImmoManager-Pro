## Core contract

- `POST /contract-wizard/drafts` saves a creator/portfolio-bound draft. Edit/review/publish/signature commands carry stable `idempotency_key` plus `expected_revision`; replay requires the same request. Published source snapshot and PDF bytes are immutable. A lost publication response can be retried without duplicate tenant/contract/document creation.
- Explicit review stores template version, source values, selected attachments, SHA256 and parameters. Publication rechecks source hash, occupancy and current rights, then creates an optional new tenant, contract, generated Document and optional unconfirmed move-in protocol together. Agreed deposit is only `Contract.deposit_amount`: no held deposit, bank booking, receipt, mandate execution, SMTP, signature-provider or transfer is inferred.
- Normal SQL/Memory contract creates and occupancy-changing updates share Property→Unit locks with publication. Drafts do not reserve. Active and terminated tenancies include their end day; a new tenancy starts the following day. Missing termination end remains reserving. Maintenance/inactive property/unit blocks activation. Metadata-only edits preserve old overlapping records.
- Chosen local originals are copied in 64-KiB chunks inside the publication transaction, with SHA256/size/source metadata. Originals may subsequently disappear without losing archived bytes. External/S3/unavailable documents require explicit metadata-only selection; no external fetch. Existing configurable `MAX_UPLOAD_SIZE_BYTES` is a technical per-file budget and can be adjusted. There is no total document/row limit.
- PDF fallback in authenticated `files.py` accepts only `contract-wizard/<UUID>.pdf`, validates current portfolio, original property/unit/tenant, contract and generated Document binding, and verifies SHA256. Original attachment downloads are completely checked into a private temporary workspace before HTTP headers; scoped streaming rechecks rights and cleans up on cancellation/disconnect.
- Manual signature evidence requires named signers/date/reference plus explicit confirmation. It records a factual administrative note and optional related Document link, not cryptographic certification; it never activates the contract. Draft publication can explicitly choose active only after occupancy checks.
- Business-only JSON import/reset refuses before mutation when these journals exist. Generated documents/contracts, related live ancestors and linked signature documents cannot be silently deleted. Complete offline database backups preserve all six tables. Root's recipient/privacy graph should explicitly include the draft snapshot, template body, command result, signers/reference/note, and attachment original bytes; do not delete journals as a shortcut.
